# История правок — nn_chat (бэкенд + web)

Человекочитаемый журнал заметных изменений. Технические детали — в git-коммитах.

## 2026-06-27

### Авторизация
- Грейс-период для refresh-токена: при ротации прежний токен ещё ~60с валиден, чтобы прерванный/повторный/параллельный рефреш не выкидывал на логин (чинило разлогин при тапе по пушу). Колонки `session_prev_token`/`session_prev_token_expires_at`, миграция `20260627_000027`.

### Realtime / синхронизация (фаза 2, бэкенд)
- Инкрементальный синк: `GET /messages/sync?cursor&limit` — изменения с курсора (живые сообщения + тумбстоуны удалённых). Колонки `message_updated_at` (+индекс) и `message_deleted_at` (soft-delete), миграция `20260627_000028`.
- SSE: `GET /messages/stream` + внутрипроцессный брокер (один воркер). События `created/updated/deleted`.
- Карточка чата = единица синка: при изменении заказа/инвентаризации/приёмки/статуса «трогается» её сообщение и эмитится SSE — статусы/позиции расходятся через один канал.
- nginx: отдельный `location` для SSE-стрима без буферизации.

### Web realtime (чат, заказы, документы)
- Один app-wide SSE-канал (`fetch`+ReadableStream, т.к. нативный EventSource не шлёт Bearer). Страницы «Заказы»/«Документы» и чат обновляются вживую.
- Резервный поллинг (5с) — гарантирует доставку app→web, когда браузерный SSE буферится прокси.
- Обновление токена на web (хранение refresh, coalesced refresh + ретрай на 401) — web больше не теряет realtime и не разлогинивает через 30 минут.
- Мгновенная очистка поля ввода при отправке сообщения.
- Фикс «залипшей» строки заказа: пере-синхронизация локального стейта строки из рефетча (цена/позиции/покупатель обновлялись только после F5; статус заказа — обновлялся).

### Деплой
- Деплой по push в `main` (GitHub Actions): pytest → сборка образов backend+web → выкатка на VPS, миграции применяются автоматически.
