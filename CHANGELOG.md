# История правок — nn_chat (бэкенд + web)

Человекочитаемый журнал заметных изменений. Технические детали — в git-коммитах.

## 2026-07-04

### Права доступа — гибкая система
- **Права по складам**: у каждого склада, к которому есть доступ, — своя настройка: область видимости (только свои / весь склад), можно ли создавать, область редактирования и удаления (свои / весь склад). Полный набор: отсутствие склада = нет доступа. Хранится в `user_establishment_roles`.
- **Разделы меню / режимы приложения** (`users.user_sections`): что видит пользователь — чат / СРМ / прайс + подразделы СРМ (заказы, товары, инвентаризация, регистрации, контакты). `null` = все разделы, пустой список = нет доступа. Веб прячет пункты меню, приложение гейтит режимы (свайп-пейджер показывает только доступные).
- **Раздаёт права только админ** (страница «Пользователи» в вебе). Админ обходит все проверки. **Вход в веб** открыт любому, у кого есть хотя бы один раздел или роль на складе (раньше — только админ).
- **Отдельная страница пользователя**: личные данные (имя/фамилия/возраст/адрес), кнопки доступа/статуса в шапке, режимы и разделы, права по каждому складу.
- **Админ может удалять сообщения в чате любого пользователя** (не только свои).

### Реалтайм-права
- Смена прав по складам или разделов/статуса пользователя рассылает SSE-событие `user_updated`; веб и приложение перечитывают `/me` и применяют доступ **на лету, без перезахода** (меню/режимы обновляются сразу). Отзыв доступа к текущему режиму в приложении возвращает на «Чат».

### Web — заказы
- **Дата заказа в 2 строки**; над датой — **ФИО создателя** заказа.
- **Трек СДЭК**: по тапу на номер — меню «Скопировать трек / Пересоздать накладную» (убрана отдельная кнопка «Пересоздать» из строки).
- **«Действие»** — выпадающий список у свёрнутых заказов (вместо одиночной «Удалить»): удалить отмеченные, скопировать позиции (с количеством и ценой / просто список).
- **Колонка «Итого»** фиксированной ширины: мультивалютное значение в одну строку с многоточием — не смещает соседние колонки (полное значение в подсказке).
- **Иконка чата заказа**: красноватая при непрочитанных, зеленоватая когда все прочитаны, + мелкий бейдж-счётчик. Оверлей чата крупнее и фиксированного размера, сообщения прижаты к низу над полем ввода.

### Каталог / производительность
- **Фоновая гидратация прайса** при интерактивном поиске: поиск сразу отдаёт локальные результаты, свежий CL из `nn_vla` подтягивается отдельным потоком (быстрый «холодный» первый поиск при создании заказа). Переиспользуемый HTTP-клиент + TTL-кэш запросов.

## 2026-07-03

### СДЭК (доставка) — новая интеграция
- **Создание накладной** (`POST /cdek/orders/{id}/waybill`): получатель, город получателя и ПВЗ (поиск по названию/адресу — без кодов), курьер/ПВЗ, габариты, тариф, доп. услуги (страхование, СМС, наложенный платёж, оплата доставки отправитель/получатель). Обе печатные формы (накладная + ШК) как **PDF падают в чат заказа** от системного пользователя `cdek_helper`.
- **Отправитель**: город + опциональный **ПВЗ сдачи** (`shipment_point`) — сдаём в ПВЗ или курьер. На проде имя/адрес отправителя берутся из договора СДЭК (не шлём); на тесте — заглушка. `GET /cdek/defaults` — последний использованный ПВЗ сдачи для подстановки по умолчанию.
- **Статусы**: авто через вебхук (`POST /cdek/webhook`, публичный, регистрируется на старте по `CDEK_WEBHOOK_URL`) + пуллинг `GET /cdek/orders/{id}/status`.
- **Пересоздание/сброс** (`DELETE /cdek/orders/{id}/waybill`): удаляет заказ в СДЭК и чистит трек/статус (данные получателя сохраняет) — спасает от тупика при невалидной накладной («Некорректный заказ»).
- **Префилл**: данные СДЭК клиента подставляются из его прошлых заказов (`GET /cdek/prefill`).
- Ключи/среда: `CDEK_BASE_URL` (тест `api.edu.cdek.ru` / прод `api.cdek.ru`), `CDEK_ACCOUNT`/`CDEK_SECURE` в GitHub-секретах.

### Web — заказы
- **Чат заказа** в оверлее (иконка 💬 в строке): просмотр и отправка сообщений внутреннего чата заказа, realtime-обновление, вложения (фото/файлы, вкл. PDF-накладные от `cdek_helper`) read-only.
- **Массовая смена статуса заказов**: у свёрнутых строк — чекбокс; отмеченным заказам меняем статус тем же bulk-селектором, что и позиции (опции переключаются на статусы заказа).
- СДЭК-накладная: оверлей создания (поля получателя/отправителя/ПВЗ/тарифа/услуг), «Пересоздать» в строке.

### Инфраструктура / конфигурация
- Стандартизирован нейминг compose: `docker-compose.yml` — локальный запуск, `docker-compose.prod.yml` — сервер. Локальный стек читает `.env` (через `${VAR:-default}`, работает и без файла); `.env.example` — локальный шаблон, прод-конфиг — только в GitHub-секрете `PRODUCTION_ENV_FILE` (переменные описаны в `DEPLOYMENT.md`).
- dev-compose: `pull_policy: never` для `backend`/`seed` (локальный образ собирается, а не тянется из реестра).

### Заказы
- Частичная отгрузка (`POST /orders/{id}/split`): в заказе остаются и «В наличии», и уже «Собрано» (раньше «Собрано» уезжало в дубль).

## 2026-07-01

### Заказы
- **Атомарный сплит частичной отгрузки** (`POST /orders/{id}/split`): «В наличии» остаются в заказе (→ «На сборку»), остальное (ожидаемые + отменённые) — в новый заказ-дубль; оба заказа переотдаются realtime.
- Устойчивость к churn каталога: заказ не падает 404 на исчезнувший товар; веб всегда шлёт снимок позиции (артикул+название) — фикс «Товар не найден».
- Аудит заказа: идентичность позиции — по артикулу, не по `product_id`.

### Комментарии заказа
- Realtime-обновление счётчика непрочитанных + пуш о новом комментарии.

### Каталог
- Федерация со свежим прайсом `nn_vla`: источник правды по номенклатуре — CL.

### Надёжность
- **Idempotency-Key** middleware: дедуп повторных `create`-POST — защита от задвоения заказов/сообщений при клиентском авто-повторе.

### Деплой / CI
- Фиксы деплоя: SSH-ключ из base64-секрета; ожидание готовности фронта в `post_deploy_check`.

## 2026-06-27

### Авторизация
- Грейс-период для refresh-токена: при ротации прежний токен ещё ~60с валиден, чтобы прерванный/повторный/параллельный рефреш не выкидывал на логин (чинило разлогин при тапе по пушу). Колонки `session_prev_token`/`session_prev_token_expires_at`, миграция `20260627_000027`.

### Realtime / синхронизация (фаза 2, бэкенд)
- Инкрементальный синк: `GET /messages/sync?cursor&limit` — изменения с курсора (живые сообщения + тумбстоуны удалённых). Колонки `message_updated_at` (+индекс) и `message_deleted_at` (soft-delete), миграция `20260627_000028`.
- SSE: `GET /messages/stream` + внутрипроцессный брокер (один воркер). События `created/updated/deleted`.
- Карточка чата = единица синка: при изменении заказа/инвентаризации/приёмки/статуса «трогается» её сообщение и эмитится SSE — статусы/позиции расходятся через один канал.
- nginx: отдельный `location` для SSE-стрима без буферизации.

### Web realtime (чат, заказы, документы)
- Один app-wide SSE-канал (`fetch`+ReadableStream, т.к. нативный EventSource не шлёт Bearer). Страницы «Заказы»/«Документы» и чат обновляются вживую.
- Резервный поллинг (5с) — гарантирует доставку app→web, когда браузерный SSE буферится прокси.
- Обновление токена на web (хранение refresh, coalesced refresh + ретрай на 401) — web больше не теряет realtime и не разлогинивает через 30 минут.
- Мгновенная очистка поля ввода при отправке сообщения.
- Фикс «залипшей» строки заказа: пере-синхронизация локального стейта строки из рефетча (цена/позиции/покупатель обновлялись только после F5; статус заказа — обновлялся).

### Деплой
- Деплой по push в `main` (GitHub Actions): pytest → сборка образов backend+web → выкатка на VPS, миграции применяются автоматически.
